# First-party rule contracts

Research and calibration date: 2026-08-30

Effect Doctor currently catalogs 155 rules: 99 from `@effect/tsgo`, 40 from `oxlint-plugin-effect`, and 16 first-party rules. The first-party rules are deliberately small, import-aware, and advisory. They fill contracts that are either outside an upstream provider or narrower than an upstream policy rule; they do not try to make the catalog look large. Effect source links below are pinned to the installed `effect@4.0.0-rc.112` release commit, `2600f62f4532026928454dcea8d1c48557b3f942`.

## Admission standard

A first-party rule is admitted only when all of the following are true:

1. An official Effect source or an independently documented product-integrity requirement states the failure model.
2. The syntax checker can prove the relevant import and local structure without guessing types or intent.
3. A public packaged scan fixture contains both a firing case and close valid cases.
4. The rule has a stable catalog identity and provider provenance.
5. A completed scan over the pinned calibration corpus has no unexplained finding.

Type-aware contracts stay in TSGo. Broad style preferences stay out. Unknown local structure causes the first-party rule to abstain.

Effect Solutions independently demonstrates the [signal-preserving adapter shape](https://github.com/kitlangton/effect-solutions/blob/09f82e6c5c928e7232cd32daf04d7c6a830b63f7/packages/website/docs/14-use-pattern.md#the-pattern). |
| `consistent-effect-fn-name` | A plain, unqualified `Effect.fn` span literal disagrees with the unambiguous identifier receiving the function, so traces name a different operation than the source API. | Qualified operation names, snake-case telemetry conventions, dynamic names, anonymous returns, computed properties, destructuring, and bindings that cannot be proven locally. | The canonical Effect guide says an [`Effect.fn` span name should match the function name](https://github.com/Effect-TS/effect/blob/145d8e1013220425b8edf34f7011c73f73e1cdcf/LLMS.md#L65-L86). |
| `no-duplicate-layer-factory-call` | The same proven zero-argument local factory is called more than once inside one Layer graph, producing distinct Layer identities and defeating reference memoization. | Different arguments, different graphs, computed or unproven callees, calls outside a Layer expression, and occurrences explicitly wrapped in `Layer.fresh`. | Effect's [Layer memoization guide](https://www.effect.website/docs/v4/requirements-management/layer-memoization/) requires reuse of one Layer value and documents `Layer.fresh` as the explicit opt-out. |
| `no-inline-schema-compile` | An immediately invoked Schema adapter inside a function also constructs a fresh, closed schema AST, so the identity-keyed parser cache cannot be reused across calls. | Stable schemas, dynamic or function-local schemas, returned adapters, factory options, computed/spread constructions, one-shot module initialization, and non-whitelisted APIs. | Effect's AI guide [hoists reusable parsers](https://github.com/Effect-TS/effect/blob/2600f62f4532026928454dcea8d1c48557b3f942/ai-docs/src/01_effect/02_schema/10_schema-basics.ts#L29-L41), while its compiler memoizer is [keyed by object identity](https://github.com/Effect-TS/effect/blob/2600f62f4532026928454dcea8d1c48557b3f942/packages/effect/src/Function.ts#L1315-L1347). The complete failure contract is recorded in [`no-inline-schema-compile.md`](./no-inline-schema-compile.md). |
| `no-multiple-callback-resume` | A locally provable execution path calls an `Effect.callback` continuation more than once; later completions are ignored. | Mutually exclusive branches, an early-return branch followed by a later completion, nested function bodies, aliased continuations, and unproven callback APIs. | The official callback guide says [`resume` should be called exactly once](https://www.effect.website/docs/v4/getting-started/creating-effects/#callback) and demonstrates that a second completion is ignored. |
| `no-mutation-after-unsafe-chunk-wrap` | A local array is directly mutated after being wrapped by `Chunk.fromArrayUnsafe`, changing data behind an ostensibly immutable Chunk. | Mutations before wrapping, indirect aliases, unknown escapes, readonly inputs, and unrelated constructors. | The official Chunk guide explains that [`fromArrayUnsafe` shares the input array](https://www.effect.website/docs/v4/data-types/chunk/#unsafefromarray) and recommends a copying constructor when mutation may follow. |
| `no-unredacted-value-in-diagnostic` | `Redacted.value` is directly embedded in a known log, error, log-annotation, or span-annotation sink, removing protection at the exact boundary where accidental disclosure is likely. | Trusted protocol boundaries, unknown sinks, indirect reveals, bare value access, shadowed imports, and diagnostic calls that preserve the wrapped value. | The official Redacted guide warns that [`Redacted.value` exposes the underlying value](https://www.effect.website/docs/v4/data-types/redacted/), the source limits it to a [trusted boundary](https://github.com/Effect-TS/effect/blob/2600f62f4532026928454dcea8d1c48557b3f942/packages/effect/src/Redacted.ts#L224-L245), and Betalyra's v4 observability proposal keeps secrets out of [span attributes](https://github.com/betalyra/effect-skills/blob/c248ce5043d6ecc08c9710f1dd39ef4edd283879/effect-best-practices-v4/references/observability-patterns.md#L132-L153). |

The executable positive and adversarial cases live in [`tests/fixtures/doctor`](../../tests/fixtures/doctor), and [`first-party-liveness.test.ts`](../../tests/first-party-liveness.test.ts) asserts that every enabled public first-party identity fires through the packaged `scanProject` seam.

## Candidate decisions

The first candidate pass produced five narrow rules and two rejections. A later complete Kit Effect skill audit added two resource-safety rules. The official-guide, Effect-blog, and community-repository passes admitted six more narrow checks. The four-source guidance audit added one escaping-throw check and extended the existing configuration and telemetry-redaction contracts; all other guidance mapped to an upstream owner, stayed project-local, or remained human design guidance.

| Candidate | Decision | Reason |
| --- | --- | --- |
| Direct known-suspending Effect passed to a synchronous runner | Accept narrowly | The runtime contract explicitly fails or dies for async work, and direct constructors are locally provable. A blanket `runSync` ban would duplicate TSGo policy and reject valid application boundaries. |
| Escaping `throw` in a confirmed Effect generator | Accept narrowly | The runtime turns the exception into an untyped defect. Locally caught throws, nested functions, indirect generators, and explicit defects remain clean. |
| JSON stringification at an Effect logging boundary | Accept narrowly | Effect loggers retain structured values. JSON serialization elsewhere is often intentional. |
| JSON string passed to an Effect text response | Accept narrowly | The first-party JSON response constructor captures serialization failure and content type. |
| Manual transaction control through a proven Effect SQL client | Accept narrowly | `withTransaction` owns connection, commit, rollback, savepoint, and interruption behavior. |
| Direct fetch adapter that definitively omits a signal | Accept narrowly | The promise adapter's cancellation contract is explicit. Arbitrary Promise APIs are not flagged because support for `AbortSignal` cannot be inferred syntactically. |
| Direct HTTP work inside a proven Effect SQL transaction | Accept narrowly | The transaction owner and direct network operation are both locally evident. Indirect calls abstain because their implementation and execution timing are unknown. |
| Proven never-ending work run as Layer acquisition | Accept narrowly | A Layer cannot finish building while its acquisition effect is still running. The rule recognizes only explicit non-termination and leaves unknown lifetimes alone. |
| Plain `Effect.fn` span name disagrees with its binding | Accept narrowly | The official guide gives an exact naming contract. Qualified and non-identifier telemetry names are intentional conventions and therefore abstain. |
| Duplicate zero-argument Layer factory call in one graph | Accept narrowly | The repeated call visibly loses Layer identity; `Layer.fresh` is the documented way to request separate acquisition. Arbitrary parameterized or unproven calls abstain. |
| Immediately invoke an adapter over a fresh closed Schema | Accept narrowly | Fresh AST identity defeats the compiler cache. Stable schemas remain clean, even when their adapter factory is written inline. |
| Multiple reachable callback completions | Accept narrowly | A second completion on one provable path is ignored. Mutually exclusive branches and nested functions require no warning. |
| Direct mutation after `Chunk.fromArrayUnsafe` | Accept narrowly | The API explicitly shares the array, and a later mutation of the same local binding is provable without alias analysis. |
| Reveal a `Redacted` value directly inside a diagnostic | Accept narrowly | The protection is visibly removed inside a known disclosure sink. Unknown and trusted non-diagnostic boundaries abstain. |
| Immediate `forkChild` followed by `Fiber.join` | Reject | Effect's own [`forkChild` example](https://github.com/Effect-TS/effect/blob/2600f62f4532026928454dcea8d1c48557b3f942/packages/effect/src/Effect.ts#L16940-L16990) uses this exact shape. It can also carry supervision and concurrency semantics that are not equivalent to simple sequencing. |
| Always replace Vitest callbacks with `it.effect` | Reject | `it.effect` is useful, but dependency choice is project policy. TSGo already blocks the actual correctness failure with `floatingEffectInVitest` and explicitly permits either an Effect-aware test API or `Effect.runPromise`. |

Related TSGo rules remain authoritative: `runEffectInsideEffect`, `preferUnsafeConstructor`, `floatingEffectInVitest`, `abortControllerInEffect`, `globalFetchInEffect`, and `preferSchemaOverJson`. Effect Doctor does not clone them. The accepted JSON and fetch rules describe narrower boundary failures, while the broader TSGo preferences remain visible in the generated catalog under their upstream identities and severities.

### Four-source delta calibration

The four-source pass reran the packaged scanner after adding the sixteenth rule and both security extensions. It completed all three providers over 2,245 configured files: Effect Doctor (62), Effect `packages/effect` (460), Effect Solutions (62), six EffectBench packages (65), three T3Code packages (136), two AnswerOverflow packages (18), Better Context server (60), Executor local (41), course-video-manager (979), and Expect (362). The repository revisions were Effect `145d8e1`, Effect Solutions `09f82e6`, EffectBench `ab1b349`, T3Code `c0e09f3`, AnswerOverflow `1b94e8f`, Better Context `864e5ba`, Executor `7cfcfef`, course-video-manager `008e227`, and Expect `39e9750`.

`no-throw-in-effect-generator` produced 20 reviewed production findings across three course-video-manager service files. Each is either a recoverable branch currently escaping the typed error channel or an invariant/exhaustiveness failure whose defect intent is implicit; the rule's recommendation distinguishes those cases by offering a yielded typed error or explicit `Effect.die`. An initial EffectBench test-only finding exposed a legitimate assertion/narrowing boundary, so `.test.*` and `.spec.*` files were added as an explicit abstention and the complete EffectBench rescan returned clean. The new `Config.schema` and telemetry-sink paths produced no non-fixture findings. Incomplete package roots were again excluded rather than counted as clean.

Zero corpus findings are evidence against noisy matching, not evidence that the rules are valuable by themselves. Before any first-party rule becomes blocking, the corpus must include independently reviewed real defects for that rule, preserve zero unexplained findings, and exercise every supported Effect version.
